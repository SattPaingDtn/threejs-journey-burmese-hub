## 👋 မင်္ဂလာပါ သူငယ်ချင်း!

Three.js Journey ရဲ့ ပထမဆုံး သင်ခန်းစာကို ရောက်ရှိလာတဲ့အတွက် အရမ်းကို ဝမ်းသာပါတယ်။ 

ကျွန်တော်တို့ ဒီသင်တန်းမှာ ဘာတွေ လုပ်ကြမလဲဆိုရင် — သာမန် ၂ ဖက်မြင် (2D) ဝက်ဘ်ဆိုက်တွေထက် အများကြီး ပိုမိုဆန်းသစ်ပြီး၊ User ကိုယ်တိုင် Mouse နဲ့ လှည့်ပတ်ကြည့်ရှုနိုင်တဲ့ **အမိုက်စား 3D Web Experiences တွေ၊ 3D Games တွေနဲ့ Interactive Websites တွေ** ကို ကိုယ်တိုင် လက်တွေ့ ဖန်တီးသွားကြမှာ ဖြစ်ပါတယ်။

ကဲ... ဘာမှ မစတင်ခင် ကျွန်တော်တို့ ကွန်ပျူတာထဲမှာ 3D ရုပ်ပုံတွေ ဘယ်လို ပေါ်လာသလဲဆိုတဲ့ အခြေခံ သဘောတရားလေးကို အရင်ဆုံး စကားပြောသလို လေ့လာကြည့်ရအောင်။

## 🧠 CPU နဲ့ GPU မတူညီပုံကို မျက်စိထဲ မြင်အောင် ကြည့်ရအောင်

3D ရုပ်ပုံတွေကို ရေးဆွဲတဲ့အခါ ကျွန်တော်တို့ ကွန်ပျူတာမှာ အဓိက အလုပ်လုပ်ပေးတဲ့ ဦးနှောက် (၂) ခု ရှိတယ်:

```
┌─────────────────────────────────────────┐     ┌─────────────────────────────────────────┐
│       🧠 CPU (Central Processing Unit)  │     │       ⚡ GPU (Graphics Processing Unit) │
├─────────────────────────────────────────┤     ├─────────────────────────────────────────┤
│ • Core အရေအတွက် နည်းတယ် (4 ~ 16 Cores)  │     │ • Core ထောင်သောင်းချီ ပါတယ် (3,000+)    │
│ • အလုပ်တစ်ခုပြီးမှ တစ်ခုကို အစဉ်လိုက်လုပ်တယ်│     │ • အလုပ်ပေါင်း သန်းချီကို တစ်ပြိုင်နက်လုပ်တယ်│
│ • JavaScript Logic နဲ့ ဖိုင်ဖွင့်တာတွေလုပ်တယ် │     │ • 3D အမှတ်တွေနဲ့ Pixel ဆေးခြယ်တာ လုပ်တယ်│
└─────────────────────────────────────────┘     └─────────────────────────────────────────┘
```

> 💡 **ဆရာ့ရဲ့ မြင်သာတဲ့ ဥပမာလေး**:  
> စဉ်းစားကြည့်ပါ... အကယ်၍ လူအယောက် ၁,၀၀၀ ကို ရေတစ်ခွက်စီ တိုက်ချင်တယ် ဆိုပါစို့ —  
> * **CPU ပုံစံ**: အရမ်း ပြေးလွှားမြန်ဆန်တဲ့ လူ ၁ ယောက်တည်းက ၁ ယောက်ပြီးမှ ၁ ယောက် အလှည့်ကျ သွားတိုက်တာပါ။  
> * **GPU ပုံစံ**: ရေခွက်ကိုင်ထားတဲ့ လူ ၁,၀၀၀ က လူ ၁,၀၀၀ စလုံးဆီကို **တစ်ပြိုင်နက်တည်း (Parallel)** သွားတိုက်လိုက်တာပါ။

3D Model တစ်ခုမှာ တြိဂံပေါင်း ထောင်သောင်းချီ (Pixel သန်းပေါင်းများစွာ) ပါဝင်တဲ့အတွက် CPU တစ်ခုတည်းနဲ့ ဆွဲရင် စက်အရမ်းလေးပြီး ထစ်သွားပါလိမ့်မယ်။ ဒါကြောင့် 3D Graphics တွေ အားလုံးကို **GPU စွမ်းအား** နဲ့ ရေးဆွဲရတာ ဖြစ်ပါတယ်။

---

## 🔑 WebGL နဲ့ Three.js ရဲ့ ဆက်စပ်မှု

### ၁။ WebGL ဆိုတာ ဘာလဲ?
WebGL ဆိုတာ Browser ထဲမှာ GPU ကို တိုက်ရိုက် ခိုင်းစေပြီး 3D ရုပ်ပုံတွေ ဆွဲပေးတဲ့ Low-level စနစ်ပါ။ ဒါပေမယ့် WebGL သီးသန့် ကုဒ်ရေးရတာ အလွန်ခက်ခဲပြီး စာကြောင်းရေ ရာချီ ရှုပ်ထွေးစွာ ရေးရပါတယ်။

### ၂။ Three.js က ကျွန်တော်တို့ကို ဘယ်လို ကယ်တင်ပေးသလဲ?
**Three.js** ဆိုတာ WebGL ရဲ့ ခက်ခဲရှုပ်ထွေးတဲ့ အလုပ်တွေကို နောက်ကွယ်မှာ အကုန် လုပ်ပေးထားတဲ့ JavaScript 3D Library ဖြစ်ပါတယ်။ ကျွန်တော်တို့က ရှုပ်ထွေးတဲ့ သင်္ချာတွေ ရေးစရာမလိုဘဲ အောက်ပါအတိုင်း ကုဒ် ၃ ကြောင်းလောက်နဲ့ 3D Cube လေးတစ်ခု ချက်ချင်း ဖန်တီးနိုင်သွားပါတယ်:

```javascript
// Three.js ဖြင့် ရေးသားရပုံ လွယ်ကူမှု
const scene = new THREE.Scene()
const mesh = new THREE.Mesh(
    new THREE.BoxGeometry(1, 1, 1),
    new THREE.MeshBasicMaterial({ color: 0xff0000 })
)
scene.add(mesh)
```

## 💡 ဆရာ့ရဲ့ အလွတ်မှတ် မှတ်စုတို (Memory Hook)

> 🧠 **ဒီလိုလေး မှတ်ထားလိုက်ပါ**:  
> * **CPU** = တစ်ခုပြီးတစ်ခု အစဉ်လိုက် စဉ်းစားတဲ့ ဦးနှောက်။  
> * **GPU** = အမှတ် သန်းပေါင်းများစွာကို တစ်ပြိုင်နက် ဆွဲပေးတဲ့ လက်ပေါင်းထောင်ချီ။  
> * **WebGL** = Browser ထဲက GPU မောင်းနှင်စက်။  
> * **Three.js** = WebGL ကို အလွယ်တကူ ခိုင်းစေနိုင်တဲ့ အကောင်းဆုံး 3D ကိရိယာ။
