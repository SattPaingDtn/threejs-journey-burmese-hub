# ၂။ ကွန်ပျူတာ ဟာ့ဒ်ဝဲ ဗိသုကာ: CPU နှင့် GPU မတူညီပုံ

3D ရုပ်ပုံတစ်ခု ဖန်သားပြင်ပေါ်မှာ ချောမွေ့စွာ ပေါ်လာဖို့ ကွန်ပျူတာထဲမှာ အဓိက အလုပ်လုပ်ပေးတဲ့ ဦးနှောက် (၂) ခု ရှိတယ်:

```
┌─────────────────────────────────────────────────────────────┐
│                 🧠 CPU (Central Processing Unit)            │
│   • Core အရေအတွက် နည်းတယ် (4, 8, 16 Cores)                  │
│   • အလွန်ရှုပ်ထွေးတဲ့ Logic တွေကို တစ်ခုပြီးမှတစ်ခု တွက်တယ် (Serial) │
│   • JavaScript Code, File Loading, User Events တွေကို တာဝန်ယူတယ်  │
└──────────────────────────────┬──────────────────────────────┘
                               │ (ညွှန်ကြားချက်များ ပေးပို့ခြင်း)
                               ▼
┌─────────────────────────────────────────────────────────────┐
│                 ⚡ GPU (Graphics Processing Unit)           │
│   • Core ထောင်သောင်းချီ ပါဝင်တယ် (2,000 ~ 10,000+ Cores)      │
│   • ရိုးရှင်းတဲ့ သင်္ချာတွေကို တစ်ပြိုင်နက်တည်း တွက်ချက်တယ် (Parallel)│
│   • 3D Vertices (အမှတ်များ) နှင့် Pixels သန်းပေါင်းများစွာ ဆေးခြယ်သည် │
└─────────────────────────────────────────────────────────────┘
```

### 💡 ဆရာ့ရဲ့ မြင်သာတဲ့ ဥပမာလေး:
စဉ်းစားကြည့်ပါ... အကယ်၍ အားကစားကွင်းကြီးတစ်ခုထဲမှာ လူအယောက် ၁,၀၀၀ ကို ရေတစ်ခွက်စီ တိုက်ချင်တယ် ဆိုပါစို့ —
* **CPU ပုံစံ**: ကမ္ဘာ့အပြေး အမြန်ဆုံး အပြေးသမား ၁ ယောက်တည်းက တစ်ယောက်ပြီးမှ တစ်ယောက် အလှည့်ကျ သွားတိုက်တာပါ။ ဘယ်လောက်ပဲ မြန်ပါစေ လူ ၁,၀၀၀ ပြည့်ဖို့ အချိန်အကြာကြီး ယူရပါမယ်။
* **GPU ပုံစံ**: ရေခွက်ကိုင်ထားတဲ့ စေတနာ့ဝန်ထမ်း လူ ၁,၀၀၀ က လူ ၁,၀၀၀ စလုံးဆီကို **တစ်ပြိုင်နက်တည်း (Parallel)** သွားတိုက်လိုက်တာပါ။ စက္ကန့်ပိုင်းအတွင်း ပြီးသွားပါလိမ့်မယ်။

3D Model တစ်ခုမှာ တြိဂံပေါင်း ထောင်သောင်းချီ (Pixel သန်းပေါင်းများစွာ) ပါဝင်တဲ့အတွက် CPU တစ်ခုတည်းနဲ့ ဆွဲရင် စက်အရမ်းလေးပြီး Frame Rate ထိုးကျသွားပါမယ်။ ဒါကြောင့် 3D Graphics တွေ အားလုံးကို **GPU စွမ်းအား** နဲ့သာ ရေးဆွဲရတာ ဖြစ်ပါတယ်။

# ၃။ WebGL ဆိုတာ ဘာလဲ? Three.js က ဘာကြောင့် ကယ်တင်ရှင် ဖြစ်လာသလဲ?

```
┌─────────────────────────────────────────────────────────────┐
│                 Three.js (JavaScript 3D Library)            │
│   Scene, Mesh, Camera, Lights, Geometries, Materials, Loaders│
├─────────────────────────────────────────────────────────────┤
│                 WebGL API (Browser Low-level Driver)        │
│             Shaders, Buffers, Draw Calls, GLSL, Matrices    │
├─────────────────────────────────────────────────────────────┤
│                 GPU Hardware (Nvidia, AMD, Apple M-Series)  │
└─────────────────────────────────────────────────────────────┘
```

### (၁) WebGL ဆိုတာ ဘာလဲ?
**WebGL (Web Graphics Library)** ဆိုတာ Browser ရဲ့ `<canvas>` Tag ပေါ်မှာ GPU စွမ်းအားကို တိုက်ရိုက် ရယူပြီး 3D ရုပ်ပုံတွေ ဆွဲပေးတဲ့ Low-level JavaScript API တစ်ခု ဖြစ်ပါတယ်။ Plugin တွေ (ဥပမာ Flash) တင်စရာမလိုဘဲ Chrome, Safari, Firefox, Edge စတဲ့ Browser တိုင်းမှာ တိုက်ရိုက် အလုပ်လုပ်ပါတယ်။

### (၂) Three.js ဘာကြောင့် ပေါ်ပေါက်လာသလဲ?
Native WebGL ကုဒ်တွေဟာ အလွန် နိမ့်ကျပြီး ရှုပ်ထွေးပါတယ်။ ရိုးရိုး တြိဂံပြားလေးတစ်ခု ဆွဲဖို့အတွက်တောင် ကုဒ်စာကြောင်းရေ ၁၀၀ ကျော် ရေးသားရပြီး၊ အလင်းရောင်၊ ကင်မရာ၊ အရိပ်တွေ ထည့်ချင်ရင် ကုဒ်ထောင်သောင်းချီ ရှုပ်ထွေးသွားပါတယ်။

၂၀၁၀ ပြည့်နှစ်မှာ **Ricardo Cabello (Mr.doob)** ဟာ အဲ့ဒီ အခက်အခဲတွေကို ဖြေရှင်းဖို့ **Three.js** ကို စတင် ဖန်တီးခဲ့ပါတယ်။ Three.js ဟာ WebGL ရဲ့ အောက်ခြေ ရှုပ်ထွေးမှုတွေကို စနစ်တကျ ကွယ်ဝှက်ပေးပြီး JavaScript နဲ့ လွယ်ကူစွာ ရေးသားနိုင်အောင် ကူညီပေးတဲ့အတွက် ကမ္ဘာ့အသုံးအများဆုံး စံ 3D Library ဖြစ်လာခဲ့ပါတယ်။

# ၈။ ဆရာ့ရဲ့ အလွတ်မှတ် မှတ်စုတို (Lesson 01 Memory Hook)

> 🧠 **ဒီလိုလေး အလွတ်မှတ်ထားလိုက်ပါ**:  
> * **CPU** = တစ်ခုပြီးတစ်ခု အစဉ်လိုက် စဉ်းစားတဲ့ ဦးနှောက်။  
> * **GPU** = အမှတ် သန်းပေါင်းများစွာကို တစ်ပြိုင်နက် ဆွဲပေးတဲ့ လက်ပေါင်းထောင်ချီ (Parallel Engine)။  
> * **WebGL** = Browser ထဲက GPU မောင်းနှင်စက်။  
> * **Three.js** = ခက်ခဲတဲ့ WebGL ကို လွယ်ကူအောင် ကူညီပေးတဲ့ အကောင်းဆုံး 3D ကိရိယာ။
